# 架构决策记录（ADR 摘要）

完整设计见 `docs/design/`。本文件只记录**有代价的取舍**——即那些"选另一条路也说得通，
但我们有明确理由"的决定。每条都写出「代价」与「何时该重新考虑」。

## ADR-001 服务端权威，不是"给前端加个后端"

**决定**：所有画布数据、凭据、执行记录都在服务端；前端是瘦终端。

**代价**：
- 必须有服务端才能用（原项目单文件即可跑）；
- 离线只能编辑草稿，不能作为唯一真源。

**为什么还是这样选**：原项目把 Key 放浏览器 + 前端直连，一次 XSS 即泄露；
且无法做限额、无法多端、无法审计。这些不是"加功能能解决"的问题。

**重新考虑的触发条件**：如果目标用户变成「纯单机、绝不联网、更在意零运维」，
可以恢复 local-first，但必须保留凭据服务端化（DIV-02 不可回退）。

## ADR-002 自研画布内核，不引入 React Flow

**决定**：DOM + SVG 自研内核，内核不 import React。

**代价**：几何/命中/状态机都要自己写并维护；短期比用现成库慢。

**为什么**：原项目 3384 行页面与 960 行节点组件的根因就是「交互状态与 React 渲染纠缠」。
现成库在「自定义节点 + 插件节点 + 5000 节点」组合下会成为瓶颈，而这是本项目的核心场景。

**强制约束**：`make lint` 里的 `check-kernel-purity.mjs` 会拒绝任何 `import react`。
破坏这条约束等于放弃性能目标。

**重新考虑的触发条件**：如果需求退化为「几千个节点的静态展示」，用库更划算。

## ADR-003 op-based 文档，不上 CRDT

**决定**：`canvas_ops` 日志 + 版本号 + 服务端权威快照；冲突分「可 rebase / 需裁决」。

**代价**：真正的多人实时协同体验不如 CRDT（冲突要用户裁决）。

**为什么**：CRDT（Yjs/Automerge）会引入体积与调试复杂度，而当前主场景是单用户多端。
op 语义本身与 CRDT 兼容，未来可平滑升级。

**重新考虑的触发条件**：协同变成核心场景（团队共同编辑同一画布）。

## ADR-004 计量用整数微元

**决定**：成本一律 `int64` 微元，价格表按「每百万 token / 每张 / 每秒」定义。

**代价**：展示时要除以 1e6，不能直接用浮点。

**为什么**：浮点累加会漂移，而对账场景（"我这个月花了多少"）恰恰需要精确。
`TestUsageAddIsInteger` 覆盖累加 1000 次仍精确。

## ADR-005 插件 iframe 沙箱，不用 Worker 或 WASM

**决定**：`<iframe sandbox="allow-scripts">`，**不加** `allow-same-origin`。

**代价**：每个插件 iframe 有内存开销；插件必须自带 UI 框架或写纯 DOM。

**为什么**：
- Web Worker 没有 DOM，绝大多数插件需要渲染；
- WASM 沙箱复杂度高，且不能直接跑现有 JS 插件；
- iframe 给出的是**浏览器级**隔离，比任何 JS 层沙箱更可信。

**重新考虑的触发条件**：出现需要高性能计算的插件（此时可另加 Worker 通道）。

## ADR-006 单一 SSE 连接多路复用

**决定**：所有实时事件走一条 `/canvases/{id}/events`。

**代价**：需要自己做多路复用与背压（可丢弃事件 vs 必须送达事件）。

**为什么**：WebSocket 需要额外的握手/心跳/重连逻辑；事件模型是单向的（服务端→前端），
SSE 天然契合，且 HTTP 基础设施（代理、鉴权、压缩）全部可复用。

**重新考虑的触发条件**：出现大量前端→服务端的低延迟消息（如协同光标高频上报）。

## ADR-007 错误码稳定枚举 + i18n 映射

**决定**：服务端返回 `{code, message, details, traceId}`，前端按 `code` 查文案。

**代价**：新增错误码要同时改三处（服务端常量、contracts/errors.yaml、两份文案）；
`check-secrets` 之外还需要一致性检查。

**为什么**：原项目靠前端解析 message 字符串猜语义，导致「改一个字就断」；
且无法本地化。

**验证**：`web/src/shared/i18n/__tests__/i18n.test.ts` 遍历全部错误码断言两份文案都存在。

## ADR-008 单一配置源 + 启动期校验

**决定**：`internal/platform/config.go` 是配置真源，启动时校验模式/驱动/密钥长度。

**代价**：启动更严格，配置写错直接起不来。

**为什么**："跑起来才发现密钥不对"是最难排查的一类问题；启动期失败是廉价的。

## ADR-009 边界常量的唯一真源

**决定**：坐标/尺寸/缩放/批量上限等只在 `internal/graph/limits.go` 定义一次。

**代价**：前端要用这些值时必须走 `/api/v1/meta` 或保持同步（由 `check-boundaries.mjs` 校验）。

**为什么**：原项目同类数值散在多处，文档写 30 秒代码是 60 秒这类问题无法自动发现。
`make boundaries` 会校验文档与代码一致。

## ADR-010 导入旧数据走 op 校验路径

**决定**：旧数据迁移产出的是 op 列表，经 `AppendOps` 落库，**没有旁路**。

**代价**：迁移可能因校验失败而需要修正数据（确实会发生，见 legacy 包里的几何修正）。

**为什么**：任何"为了导入方便而绕过校验"的做法都会变成数据一致性漏洞；
而且迁移本身是对校验规则的一次真实测试。
