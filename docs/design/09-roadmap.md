# 09 · 里程碑与验收

## 原则

- 先打通**一条最薄的端到端链路**，再横向铺功能，避免「大爆炸重写」。
- 每个里程碑结束都能自部署、能被使用、有可验证的验收标准。
- P0 只保证「画布 + 单节点生成 + 资产」闭环，其余能力按优先级叠加。

## 与原项目的对应关系

本路线图**不重新定义功能范围**：功能范围由 `10-parity-matrix.md` 决定，验收由 `11` / `13` 决定。
每个里程碑必须同时满足三件事：

1. 对等矩阵在该里程碑的条目达到 `13-verification-and-iteration.md` §2.1 的覆盖率门槛；
2. 该里程碑涉及的不变量（INV-*）有测试证明；
3. 该里程碑涉及的对抗用例（ATK-*）全绿，且新增边界各补 ≥1 条用例。

里程碑概览与矩阵条目的对应：

| 里程碑 | 对等矩阵主要章节 | 覆盖率门槛 |
| --- | --- | --- |
| M0 骨架 | 无（基础设施） | — |
| M1 画布内核与文档 | §1 页面、§2 数据模型、§3 交互（3.1–3.19、3.26–3.28） | 20% |
| M2 资产与生成闭环 | §2.4 资产、§3.20–3.25、§4.1–4.4、§4.15–4.18、§4.22 | 45% |
| M3 统一执行与多渠道 | §4.5–4.14、§4.19、§4.23–4.24、§6 工作台 | 65% |
| M4 资产库/提示词/素材 | §2.12 迁移、§5 图像工具、§7 素材、§11.3–11.4 | 80% |
| M5 插件体系 | §10 插件、§5.5 | 85% |
| M6 Agent | §9 Agent 与 MCP | 95% |
| M7 硬化与发布 | §8 配置与同步、§11 跨领域、§12 不复刻项收口 | 100% |

> 注意 M3 与 M4 的顺序调整：原路线图把「工作台」放在 M3，但工作台**共享执行引擎**，
> 因此工作台在 M3 落地是引擎的自然结果；而画布内图像工具（§5）是纯前端能力，
> 放在 M2/M4 更合适（不阻塞引擎）。这一调整已在矩阵中标注。

## M0 · 骨架（1 周）

- 仓库结构、Makefile、CI（lint / test / build / image）。
- Go 服务：配置、日志、DB 迁移、`/healthz`、`/api/v1/meta`。
- 前端：Vite + React + 路由 + API 客户端生成 + 登录页骨架。
- `contracts/openapi.yaml` 起步 + `make gen` 打通。

**验收**：`docker compose up` 后能打开登录页并看到后端版本号。

## M1 · 画布内核与文档（2–3 周）

- `internal/graph`：文档模型、op 校验、版本、rebase、op 日志、SSE 广播。
- 前端 `kernel/`：视口、场景图、命中测试、渲染分层、交互状态机、undo。
- NodeShell + 内置节点渲染（prompt / image / video / audio / group）。
- 连线（显式 Port）、框选、复制粘贴、快捷键。

**验收**：
- 5000 节点画布视口操作 ≥ 55 FPS。
- 两个浏览器窗口打开同一画布，一端编辑，另一端 ≤ 300ms 内可见。
- 断网 30s 后恢复，op 不丢且不重复。

## M2 · 资产与生成闭环（2–3 周）

- `internal/asset`：内容寻址、上传（含分片）、缩略图、Range 下载、GC。
- `internal/provider`：OpenAI 适配器（图片生成/编辑、模型列表）+ 凭据加密存储。
- `internal/exec`：DAG 编译、单节点 Run、SSE 进度、失败重试、日志。
- 前端：GenerationPanel（schema 驱动参数表单）、RunPanel 初版。

**验收**：
- 画布上「提示词节点 → 生成节点 → 图片节点」链路可跑通。
- 同一张图重复上传只占一份存储。
- 生成失败能看到分类原因（网络 / 限流 / 内容审核 / 参数错误）并可重试。
- 后端重启后，异步视频任务能继续查询。

## M3 · 统一执行与多渠道（2 周）

- Gemini 适配器、视频/音频能力、自定义 Provider 模板 + 沙箱脚本。
- 批量生成与变体（替代原项目的图片组节点方案）。
- 计量与成本、工作区限额、凭据级并发限流。
- Run 重放、取消、部分成功策略。

**验收**：
- 一个生成节点批量产出 4 张图，UI 可切换主结果，无隐藏的父子节点。
- RunPanel 显示本次 Token/张数/秒数与估算成本。
- 触发限额时返回明确错误码与提示。

## M4 · 资产库 / 提示词 / 素材（1–2 周）

- 服务端提示词抓取与归一化、全文检索、变量解析。
- 资产库页面（虚拟滚动、筛选、批量操作、拖入画布）。
- 旧数据导入器（浏览器 IndexedDB → 服务端）。

**验收**：
- 原项目用户能一键导入历史画布与图片，导入后打开与原来一致。
- 提示词搜索响应 < 200ms（服务端检索）。

## M5 · 插件体系（2 周）

- manifest 规范、注册表、分发与鉴权、签名校验。
- iframe 沙箱宿主 + 能力代理 + 权限校验 + 配额。
- SDK + 5 个官方示例插件（Markdown / SVG / HTML / 全景 / 便利贴）重写。

**验收**：
- 安装第三方插件时能看到权限清单，权限扩大需重新确认。
- 插件无法访问宿主 DOM/Cookie，无法发起未声明的网络请求。
- 画布导出的 JSON 包含 configSchema 快照，未安装插件时能给出明确提示。

## M6 · Agent（2 周）

- `internal/agent`：Session/Turn/Item 模型、工具协议、审批网关、审计。
- 前端侧边栏：消息流、工具卡片、审批、撤销。
- 本机 `canvas-agent` 精简为桥接器 + stdio MCP；服务端 MCP Streamable HTTP。

**验收**：
- 侧边栏里 Agent 能创建节点、连线、触发一次生成（需审批）。
- 每次写操作有 op 列表与影响预览，且可一键撤销。
- 断线重连后消息不重复、不丢失（幂等由主键保证）。

## M7 · 硬化与发布（1–2 周）

- 性能压测、SSE 连接泄漏排查、限流与背压。
- 备份/恢复、全量导出、密钥轮换流程。
- 文档站（架构、部署、插件开发、Agent 接入）、迁移指南。
- `v1.0.0` 发布。

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 画布内核自研成本高 | 拖慢 M1 | 内核先做「能跑通」的最小实现，几何与命中测试优先写测试；不追求一次性完美 |
| 前端重写期间功能回退 | 用户流失 | 保留原项目可运行分支；M2 结束前提供并行访问入口 |
| Provider 协议变更多 | 维护成本 | 适配器集中在 `provider/adapter/*`，用录制样本做契约测试 |
| 插件生态断裂 | 社区体验 | 官方插件全部重写并作为示例；导入器给出明确提示 |
| 协作冲突策略不完善 | 团队场景不可用 | 先做单用户多端；冲突 UI 明确告知，不做静默覆盖 |
| 成本/限额引发争议 | 信任问题 | 计量与价格表全部可见可配置，不做隐性计费 |

## 与原地项目的取舍说明

**保留**：画布交互心智、节点类型划分、工作流连线、助手侧边栏、插件概念、素材/提示词能力、MIT 开放商用。

**改变**：
- 本地存储 → 服务端权威存储（多端、可协作、可备份）。
- 前端直连模型 → 服务端统一编排（安全、可限额、可观测）。
- 浏览器 evals 插件 → 沙箱 + 权限 + 签名。
- 一次性生成调用 → 可追溯的 Run/Step/Attempt。
- 3384 行页面与 960 行节点组件 → 内核/渲染/状态分层。

## 核验挂点

- 每个里程碑末必须跑：`make parity` / `make boundaries` / `make drill`，
  并把结果记入 `docs/upstream/sync-log.md` 的里程碑小节。
- 未达覆盖率门槛或对抗用例未全绿 → 里程碑不视为完成（见 `13` §5.3 的 Done 定义）。
- 死角表（`11` §4）中任一死角若在本里程碑被触发，必须先补设计再继续。
