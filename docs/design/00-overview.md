# 00 · 总览

## 1. 背景

原项目 `infinite-canvas`（v0.18.0）是一个面向图片创作的开源工作台：无限画布 + 节点连线 + AI 生成 + 助手 + 素材 + 提示词库 + 插件系统。
功能已经相当完整，但架构上是一个**纯前端 SPA**，这带来几个天花板：

- **没有服务端**：业务数据在浏览器本地（localForage / IndexedDB），AI Key 也在浏览器，无法多端同步、无法团队协作、无法做服务端聚合与风控。
- **生成逻辑散落在前端**：`web/src/services/api/image.ts`（921 行）、`video.ts`（428 行）内联了各家接口协议、自定义脚本、重试、轮询、本地存储，协议变更与排障都在客户端。
- **单文件过大**：`pages/canvas/project.tsx` 3384 行、`canvas-node.tsx` 960 行，画布交互、生成编排、持久化、插件宿主揉在一起。
- **没有执行语义**：节点生成是「点击→请求→回填」，没有任务、没有重试策略、没有幂等、没有成本账本、没有执行历史。
- **本地 Agent 是外部包**：`canvas-agent/` 是一个独立的 Node 包，靠 SSE + HTTP 手写协议把浏览器和 Codex/Claude Code 缝在一起。

## 2. 重写目标

1. **前后端分离**：React 前端（渲染与交互）+ Go 后端（领域状态、执行、资产、协作、Agent 网关）。
2. **画布是图，工作流是一等公民**：节点图 → 可调度 DAG → 可追溯的 Run。
3. **Provider 抽象**：图片/视频/文本/音频模型统一为 Provider + Capability + Adapter，新增渠道不改核心。
4. **资产集中管理**：内容寻址存储，跨设备/跨成员共享，画布只存引用。
5. **可观测、可计费、可限额**：每次调用都有 Run 记录、Token/成本、耗时与失败原因。
6. **插件系统服务化**：从「运行时 eval 远程 JS」升级为带清单、可签名、有权限声明的插件体系。
7. **多端同步与协作就绪**：先做单用户多端同步，数据结构与事件模型为后续多人实时协同预留。

## 3. 范围

### 本期做（P0/P1）

- 工作区 / 项目 / 画布 / 节点 / 连线 / 资产 / 提示词 / Provider 凭据的完整后端领域模型。
- 画布 CRDT 友好的文档模型 + 服务端权威快照 + 增量同步。
- 执行引擎：手动画布内生成、批量生成、工作流运行。
- Provider 适配层：OpenAI 兼容（图片/视频/文本/音频）、Gemini、自定义 HTTP 脚本。
- React 画布渲染内核（DOM + SVG，命令式视口，与 React 渲染解耦）。
- 插件 SDK + 沙箱宿主（iframe / Web Worker）。
- Agent 网关：MCP Server + 侧边栏会话（Codex / Claude Code / 通用 HTTP Agent）。

### 暂不做

- 商业化计费与支付（先做成本账本，不做账单）。
- 多人实时协同编辑的冲突 UI（数据结构预留，不投入体验打磨）。
- 移动端触控专项优化（保证可用，不做手势专项）。
- 自建模型推理（只做外部 API 编排）。

## 4. 设计原则

| 原则 | 含义 |
| --- | --- |
| 领域优先 | 后端以领域模型为中心，Handler 只做协议转换 |
| 前端瘦终端 | 前端不持有任何模型凭据与调度逻辑，只做渲染 + 交互 + 事件订阅 |
| 显式状态机 | 节点与运行都有明确状态机，禁止用 `status?: string` 混合表达 |
| 幂等与可重放 | 所有写操作带幂等键，Run 记录不可变，可重放 |
| 内容寻址 | 资产用 hash 标识，去重天然成立 |
| 契约先行 | OpenAPI + SSE 事件 schema + 插件 manifest 三份契约以代码生成落地 |
| 可观测内建 | trace_id 从 HTTP 贯穿到 Provider 调用，前端每次交互可定位到后端链路 |
| 边界清晰 | 内核（graph/exec/asset）不依赖上层（api/plugin/agent） |

## 5. 关键取舍

| 议题 | 选择 | 理由 |
| --- | --- | --- |
| 画布渲染库 | 自研内核（DOM + SVG），不引入 React Flow | 原项目即为自研且需要插件节点能力，React Flow 在大量节点/自定义内容下会成为瓶颈 |
| 状态同步 | 服务端权威 + 客户端乐观更新 + 版本号增量 | 直接上 CRDT 成本高；先做版本化文档，为 CRDT 预留 op 语义 |
| 实时通道 | 单条 SSE 多路复用 | 比 WebSocket 简单、可穿透代理、天然适合「服务端 → 前端」为主的事件模型 |
| 后端框架 | Go 标准库 + chi 风格路由 | 避免重型框架，中间件需求可用 `net/http` 组合实现 |
| 类型契约 | OpenAPI 生成 TS 客户端 + 手写事件 schema | 避免双份类型漂移 |
| 前端数据层 | TanStack Query（服务端状态）+ Zustand（局部 UI 状态） | 与要重写的原项目心智一致，迁移成本低 |
| 插件沙箱 | iframe + postMessage 能力代理 | `Blob URL + import()` 时代已经过去，需要权限边界 |
